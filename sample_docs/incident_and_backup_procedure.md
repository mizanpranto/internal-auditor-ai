# Northwind Analytics Ltd - Incident Response and Backup Procedure (FICTIONAL SAMPLE)

Version 1.2 - Owner: Head of IT

## 1. Reporting security events

Anyone who notices a suspected security event, such as a phishing email, a lost laptop or unusual system behaviour, must report it immediately to security@northwind.example or call the IT service desk. Reports are logged in the incident register.

## 2. Incident classification and response

The security team assesses each report within four hours and classifies it using the severity matrix: Low, Medium, High or Critical. High and Critical incidents trigger the Incident Response Team, led by the CISO, which contains the incident, preserves logs, and coordinates communication. Where personal data is affected, the Data Protection Officer decides whether the regulator must be notified within 72 hours.

## 3. Learning from incidents

A post-incident review is held within ten working days of closing every High or Critical incident. The review records the root cause and corrective actions, which are tracked to completion by the CISO.

## 4. Backups

Production databases and file servers are backed up daily with incremental backups and a full backup every week. Backups are encrypted and stored in a separate cloud region. Backups are kept for 30 days. A restore test of a sample system is performed once a year.

## 5. Continuity

A disaster recovery plan is maintained by IT. The plan lists the critical systems and the order in which they are restored.
